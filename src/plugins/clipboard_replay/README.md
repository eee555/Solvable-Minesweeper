# clipboard_replay

监听剪贴板内容并分发给各处理器。目前支持开源扫雷网和扫雷网，识别下载链接后使用主程序打开录像。

## 使用

在插件管理器中启用 `clipboard_replay`，复制以下形式的地址即可：

```text
https://openms.top/api/video/download/1
https://new.saolei.wang/video/download/345964
```

支持正整数录像 ID，也支持包含这些链接的分享文字。当前只识别以上两站的下载接口，不处理其他网站、录像详情页或本地文件。

播放沿用历史插件的方式：启动 `src/main.py` 或 `metasweeper.exe` 并传入录像路径，由主程序的单实例入口打开录像。已有游戏会切换到录像，请留意尚未结束的对局。

## 行为

- 启用时检查当前剪贴板，之后通过 Qt 内容变化通知持续监听，不读取剪贴板历史或上传剪贴板内容。
- 每次内容变化都会按注册顺序检查全部处理器，命中者分别执行，不会在第一个命中后停止。单个处理器异常不影响其余处理器。
- 每个处理器独立去重。连续相同录像链接不会重复播放；复制其他内容后再复制原链接可以重新触发。
- 每个站点下载期间复制该站新录像链接，只保留最新的待处理录像，旧下载不再触发播放；两个站点独立管理下载任务。
- 根据响应文件名保留 `.avf`、`.evf`、`.evfs`、`.mvf` 或 `.rmv` 扩展名，不修改录像内容。
- 下载采用 HTTPS，仅允许同源重定向；单次下载最多 32 MiB、总超时 30 秒、无数据传输超时 15 秒。
- 录像只写入系统临时目录，不创建插件录像缓存。提交播放后 10 秒尝试清理临时文件，播放器启动失败时立即清理；下载取消或失败时不生成录像文件。正常退出进程时也会清理仍在等待的临时目录。文件被外部进程占用或进程被强制终止时，清理不保证成功。
- 在插件设置中关闭“监听剪贴板”可暂停识别并取消下载；退出插件时断开监听并取消下载。
- 下载或播放失败会记录在运行日志中，不会弹窗或持续重试。所有处理器共用一个运行日志页，每条消息标注时间、级别和处理器名称；日志最多保留 1000 个文本块，可手动清空。

新增插件后请重新加载或重启插件管理器。

## 开关配置

- “监听剪贴板（总开关）”控制全部处理器；关闭时取消所有未完成任务，但不改变各处理器保存的选择。
- 每个注册处理器自动生成一个独立开关，目前为“开源扫雷网录像”和“扫雷网录像”。关闭它只取消该处理器的任务，不影响其他处理器。
- 只有总开关和对应处理器开关都打开，该处理器才会工作。重新启用时会检查当前剪贴板，无须重新复制。
- 所有开关由 SDK 配置表单自动显示并持久化。保留原有总开关键 `enable_feature`，处理器键为 `enable_handler_<handler_id>`；例如 `enable_handler_openms`。
- 动态字段在配置类加载时根据注册列表生成；新增处理器后重新加载或重启插件管理器即可出现对应开关，不需要手写配置字段。

## 扩展处理器

- [plugin.py](plugin.py) 只负责剪贴板监听、分发和处理器的启停，不包含站点识别或下载逻辑。
- [handlers/base.py](handlers/base.py) 定义 `ClipboardHandler[MatchT]`，统一匹配、执行、去重和取消生命周期。
- [handlers/openms/handler.py](handlers/openms/handler.py) 和 [handlers/saolei/handler.py](handlers/saolei/handler.py) 分别定义两个站点的地址识别与下载地址。
- [handlers/download.py](handlers/download.py) 共用异步下载、临时文件、自动清理和播放逻辑。
- [replay.py](replay.py) 保留通用录像文件名检查及播放器启动功能。
- [handlers/__init__.py](handlers/__init__.py) 的 `HANDLER_TYPES` 是显式注册列表，按列表顺序分发。不依赖目录扫描或 `__subclasses__()` 的导入顺序。

新增类型时，在 `handlers` 下建立独立包，例如 `example`，导出继承 `ClipboardHandler` 的处理器类，然后加入 `HANDLER_TYPES`。

每个处理器声明 `handler_id` 和 `display_name`，分别作为稳定配置标识和设置项名称。例如 OpenMS 使用 `handler_id = "openms"`、`display_name = "开源扫雷网录像"`。新增注册项会自动生成默认开启的 `BoolConfig`；ID 不能重复，也不应随显示名称一起变更，以免丢失原有设置。未声明时使用类名作为后备标识和名称。

处理器接口：

- `match(text) -> MatchT | None`：只识别和解析；不匹配返回 `None`。结果可以是 ID、路径或自定义数据结构，不限于录像地址。
- `handle(match) -> None`：执行匹配结果。下载等耗时操作须异步执行，不得阻塞插件事件循环。
- `cancel() -> None`：取消未完成任务；有异步任务时覆写。暂停监听和插件退出时自动调用。
- `process(text) -> bool`：基类入口，按 `match → 去重 → handle` 执行，由插件调用，无须在子类重写。
- `report(message, **details) -> None`：输出自己的文本，来源名称由基类自动添加。例如 `self.report("开始解析")`，错误用 `self.report("解析失败", kind="error")`。消息通过 Qt 队列信号汇总到同一个日志框，不需要为处理器创建界面。

处理器在插件工作线程中创建，`QObject` 父对象是插件；如需 GUI 操作，仍须通过主线程信号槽或插件 SDK 调度。多个处理器可以同时命中，各自独立管理任务和重复判断。
